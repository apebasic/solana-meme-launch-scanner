# PLANS.md

## Purpose

This repository uses milestone plans to keep Codex focused and reduce token waste.

Before implementation, create or update:

- `IMPLEMENTATION_PLAN.md`

## Planning Rules

Each plan must include:

1. Objective
2. Files to create or modify
3. Step-by-step tasks
4. Tests to run
5. Acceptance criteria
6. Risks or uncertainties
7. Recovery notes
8. Checklist with checkboxes

## Execution Rules

During implementation:

- complete tasks in checklist order
- test after each meaningful checkpoint
- update `PROGRESS.md`
- do not skip failing tests
- do not mark work complete unless acceptance criteria pass
- stop and explain blockers if blocked

## Plan Format

Use this structure:

```md
# Implementation Plan — Milestone X

## Objective

## Files

## Steps

- [ ] Step 1
- [ ] Step 2
- [ ] Step 3

## Tests

## Acceptance Criteria

## Risks

## Progress Log
```

## Completion Rule

A milestone is complete only when verification commands pass and `PROGRESS.md` is updated.
